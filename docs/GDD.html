1Visão do produto

Elevator pitch

Lumen é um companion offline-first para pessoas com TDAH: registra humor, foco, rotina e medicação em segundos, correlaciona com sono/recuperação do Apple Health e gera resumos compartilháveis com o terapeuta — sem pressão, sem gamificação punitiva.

Problema

Pessoas com TDAH:

  • esquecem doses e perdem a janela de eficácia do estimulante;
  • têm dificuldade em manter diários longos;
  • chegam na terapia sem dados concretos (“foi uma semana difícil”);
  • sofrem overload sensorial e paralisia executiva sem ferramentas imediatas;
  • já geram dados ricos no Apple Health (sono, HRV, State of Mind) que ninguém interpreta no contexto TDAH.

Solução

Um único hub com:

Pilar O que faz
Check-in micro Humor + foco + energia em ~10s
Rotina do dia Âncora, micro-hábitos, água, State of Mind
Medicação Agenda, estoque, tomada/snooze/pular, janela de eficácia
Des-Trava Assistente de 3 micro-passos + timer 60s
Sono & recuperação Cards + correlações acionáveis
Hub clínico PDF, WhatsApp, card visual semanal

Não-objetivos (por enquanto)

  • Diagnóstico médico ou prescrição.
  • Rede social / feed.
  • Coach de produtividade genérico (Pomodoro agressivo, streaks punitivos).
  • Conta obrigatória na nuvem (MVP é local-first).

3Público e personas

Persona A · Usuário Primário

“Marcelo” (Adulto com TDAH, iPhone + Apple Watch)

  • Adulto com TDAH diagnosticado, em acompanhamento.
  • Usa iPhone + Apple Watch.
  • Toma estimulante (ex.: 10h de duração).
  • Quer dados objetivos para a sessão de terapia.
  • Evita apps com muitos campos obrigatórios.
Persona B · Profissional Clínico

Terapeuta & Psiquiatra (Consumidor de Dados / Relatórios)

  • Recebe PDF, texto WhatsApp ou card semanal.
  • Precisa de padrões (sono REM × paralisia, adesão, overload sensorial), não de raw dumps.
Persona C · Usuário Secundário

Usuário Android (Health Connect / Standalone)

  • Mesma UX local; Health Connect parcial; bridge State of Mind / ambiente = no-op ou vazio.

4Princípios de design (UX TDAH)

  1. Baixa fricção — ações principais em 1–2 toques; check-in cabível em bottom sheet.
  2. Sem culpa — copy sem “você falhou”; pular dose tem espaço para motivo.
  3. Uma coisa por tela/seção — home é hub; cada card leva a um job claro.
  4. Feedback imediato — haptic no Des-Trava; snackbars curtos; skeletons em vez de spinners longos.
  5. Offline-first — SharedPreferences; Health é enriquecimento, não bloqueio.
  6. Acessibilidade cognitiva — contraste alto, tipografia legível, ícones Material consistentes (AppIcons).
  7. Glass com propósito — sheets e CTAs secundários; fundo sólido (sem auras/ruído).

Ver lib/integrations/health/models/. Thresholds de insight:

  • Sono déficit: < 6h
  • REM déficit: < 75 min
  • HRV baixa: < 40 ms
  • Passos baixos: < 4000
  • Luz baixa: < 20 min
  • Ruído alto: ambiental ≥ 70 dB ou fones ≥ 80 dB

Persistência (chaves conceituais)

8Fluxos de usuário

Fluxo

F1 — Check-in matinal (caminho feliz)

Home → Check-in → valência/foco/energia/[labels] → Salvar
  → MoodRepository
  → Home atualiza “entradas recentes” + insights (se dados suficientes)
Fluxo

F2 — Rotina com mirror Health

Home → Rotina → editar âncora / SoM / hábitos / água → Salvar
  → RoutineRepository
  → RoutineHealthMirror (se HS enabled)
      → writeWater / writeMindfulness / writeStateOfMind
Fluxo

F3 — Tomar medicação

Home → Medicações → card dose pendente → Tomar
  → log.takenAt = now; estoque--; EfficacyWindowBar
  → (opcional) writeDoseEvent Apple
Fluxo

F4 — Paralisia executiva

Home → Des-Trava → passo 1 → timer 60s → passo 2 → passo 3 → snack
Fluxo

F5 — Preparar sessão clínica

Home → Hub terapeuta → (config telefone) → WhatsApp | Share card | PDF
Fluxo

F6 — Conectar Apple Health

Consent sheet → permissions plugin + bridge → syncEnabled=true
  → invalidate sleep/recovery providers

14Critérios de aceite e qualidade

Aceite por feature (checklist genérico)

  1. Funciona offline (exceto dados Health).
  2. Strings em app_pt.arb + doloc rodado se novas chaves.
  3. Light + dark sem overflow / contraste ilegível.
  4. Empty / loading / error states cobertos.
  5. Não bloqueia UX se Health negar permissão.
  6. Sem emojis decorativos novos (preferir AppIcons); exceção legado efficacy ⚡ — migrar quando possível.

Definition of Done (release)

  • flutter analyze limpo
  • Testes críticos passando
  • Privacy copy alinhada ao que o app realmente lê/escreve
  • README + este GDD atualizados se mudou escopo

Métricas de produto (sugeridas — ainda não instrumentadas)
